Emitter

DeepSpaceTelemetry.Emitter — Module
Emitter

The satellite-side loop: payload generation and batching, onboard queue management (live FIFO with absolute priority, archive LIFO backfill), link-gated transmission under the in-flight cap, and ground-truth gen/tx event logging. Re-entrant: a restarted emitter reconstructs its queues and counter from the run directory and event log.

DeepSpaceTelemetry.Emitter.pre_populate — Function
pre_populate(instrument, start_sim_time, run_dir; batch_size, kwargs...) -> (instrument, pending_segments)

Fills the on-board recorder (<run_dir>/onboard/) with the ARCH_ batches produced during the initial downtime, the backlog the active mission window starts with. run_dir is the absolute path of the run directory (TelemetryCore.run_directory).

instrument is the VirtualInstrument.InstrumentState anchored at the start of the blind spot (instrument_epoch); the pre-population runs from that anchor to start_sim_time, and an instrument anchored at or after start_sim_time returns at once with no batch written.

Returns the instrument together with any trailing segments that did not fill a complete batch. Both must be handed to run_emitter, which completes the partial batch in the mission phase.

Keyword arguments

  • batch_size: segments per batch (required).
  • markers: event markers, stamped into the batch holding their instant.
  • generation_gaps: scheduled (start, stop) intervals without data production (skip_generation_gaps!).
  • onboard_capacity_batches: recorder ceiling; data beyond it is discarded.
  • hole_feed: the declared-hole feed the emitter appends its scheduled and recorder gaps to, nothing for none. A scheduled gap inside the blind spot is declared at start_sim_time; a recorder gap opened here is declared by run_emitter when it closes.
  • progress: draw the progress bar on a terminal stderr; off for runs without a console, such as the members of a sweep.

DeepSpaceTelemetry.Emitter.skip_generation_gaps! — Function
skip_generation_gaps!(vi, pending, gaps, run_dir; hole_feed = nothing, declared_at = nothing) -> Bool

Scheduled generation gap: when the instrument's next content instant lies inside one of gaps ((start, stop) intervals), the segments of the incomplete batch are discarded (as in an emitter outage, so batch geometry stays uniform) and the content clock resumes at the first segment boundary at or after the gap's end (VirtualInstrument.advance_to!): the sampling phase of the payload origin is kept, so segment identifiers and payload rows continue on the same grid. The gap is bounded in events_tx.csv (Batch = SCHEDULED) by gap_start at the first discarded epoch (or the content end when nothing was pending) and gap_end at the resumption instant, so [gap_start, gap_end) is exactly the content not recorded. With a hole_feed, the same interval is appended to the declared-hole feed as a scheduled hole declared at declared_at (the resumption instant when nothing). Returns true when a gap was skipped.

DeepSpaceTelemetry.Emitter.transmit_onboard! — Function
transmit_onboard!(live_queue, arch_queue, link, sim_t, run_dir; max_inflight_batches,
                  onboard_count = nothing) -> Int

Places on-board batches on the downlink while link is transmittable at sim_t (visibility and no blackout). Free in-flight slots, the link/ listing below max_inflight_batches (a slot frees the moment the receiver moves a batch out), are refilled from live_queue (FIFO, absolute priority), then from arch_queue (held newest first, so the archive drains LIFO). Each move from onboard/ to link/ is appended to events_tx.csv as a tx row and taken off onboard_count. Returns the number of batches placed.

DeepSpaceTelemetry.Emitter.run_emitter — Function
run_emitter(clock, link, run_dir, instrument; batch_size, kwargs...)

The spacecraft loop: segments from instrument (synthetic, or read from an external CSV) are batched and placed on the downlink, live FIFO with absolute priority over the archive LIFO (transmit_onboard!). link is the composite ChannelEffects.LinkModel (visibility × disruption timeline): a batch finalized while the link is transmittable is stamped LIVE_, any other ARCH_, so the batches generated during a disruption blackout accumulate onboard. run_dir is the absolute path of the run directory.

instrument is the VirtualInstrument.InstrumentState the stream continues from: on the first start the one returned by pre_populate; on a restart the instrument VirtualInstrument.resumed at the first segment boundary at or after the current mission time, with the payload origin of the first start, which leaves a genuine generation gap.

clock is the TelemetryCore.TickClock of the mission, paced or not: in wall mode the driver (TelemetryCore.run_ticks!) holds each wakeup back to its wall instant, which changes when the loop runs but not what it produces. Generation is paced by the mission clock, not by the loop's own start: a segment is produced once the clock has passed the end of its content interval (vi.last_t + segment_duration_sec). While no segment is due the loop serves the downlink and parks the task (TelemetryCore.wait_until!) until that instant or the next boundary of the payload grid, whichever comes first, so a scheduled generation gap interrupts production but not transmission. The loop ends at the horizon, on the stop flag, or on the HALT sentinel (TelemetryCore.loop_should_stop).

Keyword arguments

  • batch_size: segments per batch (required).
  • pending_segments: the partial batch returned by pre_populate.
  • stop: cooperative stop flag raised by the supervisor.
  • max_inflight_batches: cap on batches simultaneously on the link.
  • markers: event markers, stamped into the batch holding their instant. The synthetic payload flags them through the instrument (VirtualInstrument.FlaggedSignal), not through this argument.
  • generation_gaps: scheduled (start, stop) intervals without data production (skip_generation_gaps!).
  • onboard_capacity_batches: recorder ceiling; new data is discarded while the buffer holds that many batches.
  • hole_feed: the declared-hole feed for the scheduled and recorder gaps, nothing for none. A scheduled gap is declared at the mission instant it is skipped at, a recorder gap at the finalization that closes it.
  • onboard_count: the number of batches on board, set from the census at start and kept in step with every write to and move out of onboard/; the receiver reads it for the metrics instead of listing the directory.
