Metrology

DeepSpaceTelemetry.Metrology — Module
Metrology

Analysis metrics derived from a run's ground-truth event logs. The first metric is the alert-latency curve: for a transient caught in a live batch, how long after the event the whole look-back window of δ before it is on the ground — under the realized live-FIFO / archive-LIFO doctrine and under a counterfactual first-in, first-out drain that re-assigns the same service completions in content order. The second is the measurement-to-ground delay of every batch against a delivery requirement (the Definition Study Report's 24 hours; Colpi et al. 2024, doi:10.48550/arXiv.2402.07571). See alert_latency_table, plot_alert_latency, delivery_delay_table, and plot_delivery_delay.

DeepSpaceTelemetry.Metrology.BatchDelivery — Type
BatchDelivery

One batch in the delivery schedule: identity, content interval, generation (finalization) instant, realized ground availability (nothing when the batch never reached the ground), and the counterfactual FIFO availability (nothing when the FIFO drain never reaches it within the mission).

DeepSpaceTelemetry.Metrology.delivery_schedule — Function
delivery_schedule(run_dir::String) -> Vector{BatchDelivery}

Per-batch delivery bookkeeping from events_tx.csv, events_rx.csv, and the batch metadata, sorted by content epoch. The realized availability is the first ingested record of the batch. The counterfactual FIFO availability re-assigns the realized service completions (the sorted ingested instants) to the batches in content order: each completion goes to the oldest batch that had been generated by then and is still undelivered under FIFO, on the run's own link and slots without live priority. Batches without a recorded content epoch (pre-content_epoch metadata) take generation − batch span.

DeepSpaceTelemetry.Metrology.completion_curves — Function
completion_curves(schedule, alert_idx, t_m, steps, span, first_epoch) -> (real, fifo)

Window-completeness latencies of one alert — the batch schedule[alert_idx] with event instant t_m — on the look-back grid δ = 0, span, …, steps·span: for each δ, the instant (hours after t_m) at which every batch overlapping [t_m − δ, t_m) plus the alert batch itself has reached the ground, under the realized deliveries (real) and the counterfactual FIFO drain (fifo). Entries are nothing once the window contains a batch that never arrived under that doctrine (each curve independently); the vectors stop where the window would reach before first_epoch, and are empty when the alert batch reached the ground under neither doctrine.

DeepSpaceTelemetry.Metrology.marker_latency_table — Function
marker_latency_table(run_dir::String; lookback_hours = 72.0) -> DataFrame

Window-completeness latency of every event marker of the run (markers.csv): Label, Marker (the instant), Batch (the batch whose content span holds it; empty when none does), Lookback_Hours, and LIFO_Hours / FIFO_Hours — completion_curves evaluated with the marker instant as t_m, so the latency counts from the event itself. Missing values mark an undelivered alert batch or a window containing a batch that never arrived; one row with Lookback_Hours = 0 and missing latencies records a marker outside every batch. Empty when the run has no markers.

DeepSpaceTelemetry.Metrology.alert_latency_table — Function
alert_latency_table(run_dir::String; lookback_hours = 72.0) -> DataFrame

Window-completeness latency curves over the look-back grid δ = 0, D, 2D, … (D = the batch content span) up to lookback_hours. Every live batch delivered under both doctrines defines an alert whose event instant t_m is the batch's content end (the moment the transient's samples exist). The look-back window [t_m − δ, t_m), together with the alert batch itself, is complete on the ground once every batch overlapping it has arrived; the latency is that completion instant minus t_m, for the realized doctrine and for the counterfactual FIFO drain (delivery_schedule). For δ ≤ D it is the delivery delay of the live batch itself, and it is non-decreasing in δ. At each δ an alert is excluded when its window reaches before the first recorded batch or holds a batch that never arrived under one of the two doctrines; N_Alerts counts the rest. Columns: Lookback_Hours, N_Alerts, and the median and 25 % / 75 % quantiles of the latency in hours for LIFO (realized) and FIFO.

DeepSpaceTelemetry.Metrology.plot_alert_latency — Function
plot_alert_latency(run_dir::String; lookback_hours = 72.0, processing_latency_hours = 1.0, style, plots_dir, formats, suffix) -> Union{Nothing,String}

Renders <plots_dir>/alert_latency.png with a vector twin from alert_latency_table and marker_latency_table: the median window-completeness latency and its interquartile band against the look-back, realized in the archive color (solid) and counterfactual FIFO in PlotTheme.COLOR_COUNTERFACTUAL (dotted), one PlotTheme.COLOR_MARKER curve per event marker, and the medians at the largest look-back annotated with the ground processing budget processing_latency_hours. Returns the PNG path, or nothing when the run holds no delivered live batch.

DeepSpaceTelemetry.Metrology.requirement_label_occupancy — Function
requirement_label_occupancy(curves, xa::Real, xb::Real) -> Vector{Tuple{Float64,Float64}}

Relative height intervals the drawn step curves of the delivery-delay figure cover over the abscissa band [xa, xb], one per curve present there. curves holds (x, y, drawn) triples of non-decreasing step data starting at the origin, each value holding from its abscissa to the next (the :post step of the drawn stairs); a curve whose last abscissa precedes the band is absent, one ending inside it covers up to its last value. Heights are divided by Y_HEADROOM, the figure's upper limit.

DeepSpaceTelemetry.Metrology.requirement_label_slot — Function
requirement_label_slot(intervals, floor::Real, extent::Real) -> Union{Nothing,Tuple{Float64,Symbol}}

Free slot for the delivery-delay figure's requirement label on one side of its rule: the relative ordinate of the anchor and the horizontal alignment of the rotated text (:right, the label hangs from the anchor; :left, it rises from it; :center), or nothing when the side holds no slot. intervals are the relative height intervals the curves occupy across the label's footprint on that side (requirement_label_occupancy), floor the relative height below which the rule is hidden (the corner annotation's top, or 0), extent the label length as a fraction of the axis height. The slot is above the highest interval when the room up to the frame holds the label with REQUIREMENT_LABEL_MARGIN at both ends, else below the lowest when the room down to floor does, else the middle of the widest gap between two intervals when it does.

DeepSpaceTelemetry.Metrology.requirement_label_anchor — Function
requirement_label_anchor(left, right, floor_left::Real, floor_right::Real, extent::Real) -> Tuple{Float64,Symbol,Symbol}

Anchor of the delivery-delay figure's vertical requirement label: the relative ordinate, the horizontal alignment of the rotated text, and the side of the rule it stands on (:left or :right). left and right hold the height intervals the curves occupy across the label's footprint on each side (requirement_label_occupancy), floor_left and floor_right the heights below which the rule is hidden there, extent the label length as a fraction of the axis height. The label takes the first slot requirement_label_slot finds, on the left of the rule before the right, and the top of the left side when neither holds one.

DeepSpaceTelemetry.Metrology.delivery_delay_table — Function
delivery_delay_table(run_dir::String) -> DataFrame

Measurement-to-ground delay of every generated batch: Batch, Live, ContentEnd, AvailableAt (missing when the batch never reached the ground), Delay_Hours = availability minus content end (missing when undelivered), and LowLatency — whether the batch reached the ground inside a low-latency period of the run's contact model. Built on delivery_schedule; rows sorted by content epoch.

DeepSpaceTelemetry.Metrology.delivery_compliance — Function
delivery_compliance(table::DataFrame, requirement_hours::Float64) -> NamedTuple

Summary of a delivery_delay_table against a delivery requirement: generated, delivered, within (delivered within requirement_hours of measurement), via_low_latency (delivered inside a low-latency period), fraction_within (of all generated batches — an undelivered batch is non-compliant), median_hours, and p95_hours of the delivered delays (NaN when nothing was delivered).

DeepSpaceTelemetry.Metrology.write_metrology_tables — Function
write_metrology_tables(run_dir::String; lookback_hours::Float64 = 72.0) -> Nothing

Writes the metrology tables of a run: alert_latency.csv and, when the run has event markers with an alert, alert_latency_markers.csv (alert_latency_table, marker_latency_table), and delivery_delay.csv (delivery_delay_table). A table that would be empty (no delivered live batch, no generated batch) is not written and is announced with a [POST] warning. The tables are run products independent of the figure flags; plot_alert_latency and plot_delivery_delay write none.

DeepSpaceTelemetry.Metrology.plot_delivery_delay — Function
plot_delivery_delay(run_dir::String; requirement_hours = 24.0, style, plots_dir, formats, suffix) -> Union{Nothing,String}

Renders <plots_dir>/delivery_delay.png with a vector twin from delivery_delay_table: the empirical distribution of the measurement-to-ground delay as the fraction of generated batches on the ground within a given delay, one curve per batch family and, when both exist, one for all batches, with the requirement rule and the compliance summary. The legend is omitted for a single curve. Returns the PNG path, or nothing when the run generated no batch.
