Metrology

DeepSpaceTelemetryHeadless.Metrology — Module
Metrology

Analysis metrics derived from a run's ground-truth event logs. The alert-latency curve gives, for a transient caught in a live batch, the time after the event at which the look-back window of length δ before it is on the ground, under the realized live-FIFO / archive-LIFO doctrine and under a counterfactual first-in, first-out drain of the same service completions. The delivery delay compares the measurement-to-ground delay of every batch with a delivery requirement (the Definition Study Report's 24 hours; Colpi et al. 2024, doi:10.48550/arXiv.2402.07571). See alert_latency_table and delivery_delay_table; the figures are drawn by DeepSpaceTelemetry.MetrologyFigures.

DeepSpaceTelemetryHeadless.Metrology.BatchDelivery — Type
BatchDelivery

One batch in the delivery schedule: identity, content interval, generation (finalization) instant, realized ground availability (nothing when the batch never reached the ground), and the counterfactual FIFO availability (nothing when the FIFO drain never reaches it within the mission).

DeepSpaceTelemetryHeadless.Metrology.delivery_schedule — Function
delivery_schedule(run_dir::String) -> Vector{BatchDelivery}

Per-batch delivery bookkeeping from events_tx.csv, events_rx.csv, and the batch metadata, sorted by content epoch. The realized availability is the first ingested record of the batch. The counterfactual FIFO availability re-assigns the realized service completions (the sorted ingested instants) to the batches in content order: each completion goes to the oldest batch that had been generated by then and is still undelivered under FIFO, on the run's own link and slots without live priority. Batches without a recorded content epoch (pre-content_epoch metadata) take generation − batch span.

DeepSpaceTelemetryHeadless.Metrology.completion_curves — Function
completion_curves(schedule, alert_idx, t_m, steps, span, first_epoch) -> (real, fifo)

Window-completeness latencies of the alert schedule[alert_idx], with event instant t_m, on the look-back grid δ = 0, span, …, steps·span: for each δ, the instant (hours after t_m) at which every batch overlapping [t_m − δ, t_m) plus the alert batch itself has reached the ground, under the realized deliveries (real) and the counterfactual FIFO drain (fifo). Entries are nothing once the window contains a batch that never arrived under that doctrine (each curve independently); the vectors stop where the window would reach before first_epoch, and are empty when the alert batch reached the ground under neither doctrine.

DeepSpaceTelemetryHeadless.Metrology.marker_latency_table — Function
marker_latency_table(run_dir::String; lookback_hours = 72.0) -> DataFrame

Window-completeness latency of every event marker of the run (markers.csv): Label, Marker (the instant), Batch (the batch whose content span holds it; empty when none does), Lookback_Hours, and LIFO_Hours / FIFO_Hours, completion_curves with the marker instant as t_m. Missing values mark an undelivered alert batch or a window containing a batch that never arrived; one row with Lookback_Hours = 0 and missing latencies records a marker outside every batch. Empty when the run has no markers.

DeepSpaceTelemetryHeadless.Metrology.alert_latency_table — Function
alert_latency_table(run_dir::String; lookback_hours = 72.0) -> DataFrame

Window-completeness latency curves over the look-back grid δ = 0, D, 2D, … (D = the batch content span) up to lookback_hours. A live batch defines an alert whose event instant t_m is the batch's content end (the moment the transient's samples exist). The look-back window [t_m − δ, t_m), together with the alert batch itself, is complete on the ground once every batch overlapping it has arrived; the latency is that completion instant minus t_m, for the realized doctrine and for the counterfactual FIFO drain (delivery_schedule). For δ ≤ D it is the delivery delay of the live batch itself, and it is non-decreasing in δ. At each δ an alert is excluded when its window reaches before the first recorded batch.

Two populations enter the table. The complete-case columns, N_Alerts and the median and 25 % / 75 % quantiles of the latency in hours for LIFO (realized) and FIFO (LIFO_Median_Hours, …, FIFO_Q75_Hours), are conditional on windows delivered in full under both doctrines: their alerts are the live batches delivered under both, and at each δ an alert whose window holds a batch that never arrived under one of the two is left out. The Kaplan–Meier columns use every alert, a live batch delivered under the realized doctrine (N_Alerts_All counts them at each δ). Under each doctrine a window that holds an undelivered batch is censored at the run end, T_end − t_m with T_end the mission end, and a window that holds data discarded at the on-board recorder (recorder_spans) never completes, nor, under the realized doctrine, one that holds a batch lost after its last retransmission (the counterfactual drain reassigns the transfers and may deliver it); N_Censored_LIFO and N_Censored_FIFO count both kinds, and LIFO_KM_Median_Hours, LIFO_KM_Q25_Hours, LIFO_KM_Q75_Hours and their FIFO counterparts are quantiles of the product-limit estimate (km_quantile). The estimator assumes censoring independent of the latency, which a backlog at the run end violates in part (late alerts are censored early), so the Kaplan–Meier median is an estimate, and "not reached" (NaN) is itself a result. One row per δ with N_Alerts_All > 0; on rows with N_Alerts = 0 the complete-case quantiles are NaN. Empty when the run has no alert.

DeepSpaceTelemetryHeadless.Metrology.delivery_delay_table — Function
delivery_delay_table(run_dir::String) -> DataFrame

Measurement-to-ground delay of every generated batch: Batch, Live, ContentEnd, AvailableAt (missing when the batch never reached the ground), Delay_Hours = availability minus content end (missing when undelivered), LowLatency — whether the batch reached the ground inside a low-latency period of the run's contact model, also where the period overlaps a nominal pass — and Due: whether content_end + delivery_requirement_hours falls at or before the mission end, so that the requirement could be checked within the run. Built on delivery_schedule; rows sorted by content epoch.

DeepSpaceTelemetryHeadless.Metrology.delivery_compliance — Function
delivery_compliance(table::DataFrame, requirement_hours::Float64; discarded::Int = 0) -> NamedTuple

Summary of a delivery_delay_table against a delivery requirement: generated, delivered, within (delivered within requirement_hours of measurement), via_low_latency (delivered inside a low-latency period), fraction_within (of all generated batches — an undelivered batch is non-compliant), median_hours, and p95_hours of the delivered delays (NaN when nothing was delivered); due (batches with Due), pending (undelivered and not yet due), discarded (the keyword, the batches discarded at the on-board recorder, discarded_batches), and fraction_within_resolved (NaN when its denominator is 0). due, pending, and fraction_within_resolved are missing for a table without the Due column (an older run). fraction_within counts every generated batch, so a batch generated less than the requirement before the end of the run counts as non-compliant although it is not yet due. fraction_within_resolved counts the batches that were due or delivered by the end of the run and the discarded ones: within / (generated − pending + discarded).

DeepSpaceTelemetryHeadless.Metrology.km_quantile — Function
km_quantile(times::AbstractVector{<:Real}, observed::AbstractVector{Bool}, p::Real) -> Float64

The p-quantile of the Kaplan–Meier product-limit estimate of the distribution of times, where observed[i] is false for a time censored at times[i] (the true value exceeds it): the smallest observed time t with Ŝ(t) ≤ 1 − p, Ŝ the estimated survival function. At an equal time events precede censorings. NaN when Ŝ stays above 1 − p (the quantile is not reached within the follow-up) or when times is empty. Kaplan & Meier (1958), doi:10.1080/01621459.1958.10501452.

source
DeepSpaceTelemetryHeadless.Metrology.recorder_spans — Function
recorder_spans(run_dir::String) -> Vector{Tuple{DateTime,DateTime}}

The content intervals [start, stop) the on-board recorder discarded at its ceiling, from the RECORDER gap rows of events_tx.csv; a span still open at the end of the log closes at the mission end. The parts of a span that a scheduled generation gap (SCHEDULED rows) covers held no data and are left out. A stream gap of an emitter outage is not: it starts at the content end of the last batch, which during an overflow is where the recorder began to discard.

source
DeepSpaceTelemetryHeadless.Metrology.discarded_batches — Function
discarded_batches(run_dir::String) -> Int

The number of whole batches the on-board recorder discarded at its ceiling: the length of the recorder_spans over the batch content span.

DeepSpaceTelemetryHeadless.Metrology.write_metrology_tables — Function
write_metrology_tables(run_dir::String; lookback_hours::Float64 = 72.0) -> Nothing

Writes the metrology tables of a run: alert_latency.csv and, when the run has event markers with an alert, alert_latency_markers.csv (alert_latency_table, marker_latency_table), and delivery_delay.csv (delivery_delay_table). A table that would be empty (no delivered live batch, no generated batch) is not written and is announced with a [POST] warning. The tables are run products independent of the figure flags; the metrology figures of the main package (MetrologyFigures) write none.
