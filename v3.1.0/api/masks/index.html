Masks

DeepSpaceTelemetry.Masks — Module
Masks

The batch-state products of a run: the replay of every batch's state (future, onboard, link, ground, lost) from the event logs, the 2D mask timeline it writes, the batch epoch map, the gap table of the delivered record, the label-span table of the scenario's labeled intervals, and the point-wise 0/1 availability expansion of one timeline row.

DeepSpaceTelemetry.Masks.BatchStates — Type
BatchStates

Alias for the per-snapshot batch-location record shared by the mask generator and the GIF animation: batch-ID vectors for every (stage × stream) bucket plus the terminal lost bucket.

DeepSpaceTelemetry.Masks.reconstruct_batch_states — Function
reconstruct_batch_states(run_dir::String, df::DataFrame; rows = 1:nrow(df))

Exact replay of every batch's location from the ground-truth event logs: the gen/tx milestones of events_tx.csv (emitter) and the ingested/lost milestones of events_rx.csv (receiver); the state-preserving retry and pruned rows are skipped. Returns one BatchStates record per requested mission_profile.csv row, in the order of rows, evaluated at that row's SimTime; the identifiers of each bucket are sorted ascending (order within a bucket is not part of the contract). Each loss is attributed to its batch ID, which gives mask state 4 = Lost. Emitter and receiver stamp milestones from separate clock reads, so recorded timestamps can invert within a batch at high speed-up; the replay enforces per-batch causal order (gen → tx → terminal) with later stages absorbing, keeping every batch's state sequence monotone. Events at the same instant are applied in causal order. The streaming form, which keeps no record per row, is replay_batch_states.

DeepSpaceTelemetry.Masks.replay_batch_states — Function
replay_batch_states(f, run_dir::String, df::DataFrame) -> Int

Streams the exact event-log replay over the metrics frame df. For every row i, once the events up to df.SimTime[i] are applied, f(i, codes, live) is called with codes::Vector{Int8}, the state of every batch identifier (0 future, 1 onboard, 2 link, 3 ground, 4 lost), and live::BitVector, whether the batch is live; both are indexed by batch identifier up to the largest identifier among the events the replay applies (those not later than the last SimTime of df), which is returned, and both are reused between calls, so f copies what it keeps. Events of unparsable batch names (identifier 0) are ignored. The event ordering and the per-batch causal rule are those described at reconstruct_batch_states.

batch_states(run_dir::String, df::DataFrame; rows = 1:nrow(df)) -> Vector{BatchStates}

Batch-location history of a run: the exact event-log replay (reconstruct_batch_states) over the metrics frame df, for the metrics rows rows. Runs without events_tx.csv (pre-0.9 layouts) are not supported and raise an ArgumentError.

DeepSpaceTelemetry.Masks.generate_telemetry_masks — Function
generate_telemetry_masks(run_dir::String)

Writes the replay of the LIFO/FIFO transmission state machine (batch_states) as the 2D matrix telemetry_mask_timeline.csv: rows are time steps, columns the Batch_IDs, entries the batch's location (0=Future, 1=Onboard, 2=Link, 3=Ground, 4=Lost). The rows are streamed from replay_batch_states to disk, so the matrix is never held in memory. Also writes the batch-epoch map masks/batch_epochs.csv; returns without output, with a warning, when mission_profile.csv is absent.

DeepSpaceTelemetry.Masks.GAP_CAUSES — Constant
GAP_CAUSES

The values of the Cause column of gap_table: lost (retry budget exhausted), pruned (payload removed by the retention custodian), undelivered (generated, on board or on the link at run end), stream (emitter outage), scheduled (a scheduled generation gap), recorder (on-board recorder overflow), and not_generated (an external record not exhausted by run end).

DeepSpaceTelemetry.Masks.gap_table — Function
gap_table(run_dir::String) -> DataFrame

Every hole of the delivered record of a run, as declared intervals with their cause: columns Cause (GAP_CAUSES), Batch (the batch of a batch-level hole, missing for a generation gap or the unreached tail), RowFirst and RowLast (payload rows, inclusive), and ContentStart, ContentEnd (the content interval [ContentStart, ContentEnd)), sorted by RowFirst. Batch rows come from the payload_row stamp of the batch metadata; generation gaps from the gap_start / gap_end pairs of events_tx.csv, a gap left open at run end closed at the mission's end; the unreached tail from external_data_rows of the snapshot. The rows of the table and the rows no delivered batch covers are the same set. On a finished run the declared-hole feed holes.csv, settled by settle_hole_feed!, holds the same holes with the instant each was declared at.

DeepSpaceTelemetry.Masks.settle_hole_feed! — Function
settle_hole_feed!(run_dir::String; table = gap_table(run_dir)) -> Int

Appends to holes.csv, the declared-hole feed, every row of gap_table it does not yet hold, with the nominal mission end (TelemetryCore.mission_end) as DeclaredAt: the end-of-run causes a feed cannot announce during the run (undelivered, not_generated) and a recorder gap still open at the mission's end. On a finished run the feed then holds every hole of masks/gaps.csv, and hole_feed_excess lists any row it holds beyond them. Idempotent: a second call appends nothing. Returns the number of rows appended. table is the gap table when the caller has derived it already.

source
DeepSpaceTelemetry.Masks.hole_feed_excess — Function
hole_feed_excess(run_dir::String; table = gap_table(run_dir)) -> DataFrame

The rows of holes.csv beyond the holes of gap_table: every row whose (Cause, Batch, RowFirst, RowLast) the table does not derive, and every repeat of a hole the feed already holds, in feed order with the feed's columns. Empty on a sound finished run, where the settled feed and the table hold the same holes. The table is the reference: its rows are exactly the rows no delivered batch covers, a property the feed, a log of declarations, cannot assert of itself. Post-processing reports a non-empty excess as a warning in the run log and leaves both files as they are. table is the gap table when the caller has derived it already.

DeepSpaceTelemetry.Masks.LABEL_SPAN_CLASSES — Constant
LABEL_SPAN_CLASSES

The values of the Class column of label_span_table: initial_downtime (the blind spot before the mission epoch), label (a [[labels]] span of the scenario), blackout and recovery (the two phases of a link disruption), generation_gap (a scheduled generation gap as configured), contact (a scheduled contact pass), and low_latency (a low-latency period, scheduled or triggered by a marker).

DeepSpaceTelemetry.Masks.label_span_table — Function
label_span_table(run_dir::String) -> DataFrame

Every labeled interval the scenario of a run declares, on the payload grid of gap_table: columns Class (LABEL_SPAN_CLASSES), Type, Label, RowFirst, RowLast (payload rows, inclusive), ContentStart, ContentEnd (the interval [ContentStart, ContentEnd)), sorted by RowFirst, RowLast, Class, Label. The table is derived from the run's configuration snapshot alone. Time intervals are taken as half-open and clipped to the mission record, rows 1 to the row before the mission end; [[labels]] spans keep their configured rows verbatim. Type is the disruption type for blackout, recovery, and generation_gap, pass for a contact, triggered or scheduled for a low-latency period, and empty otherwise; Label is the configured label. A generation gap is the configured span from start_day over duration_hours; the realized gap of masks/gaps.csv may differ from it by the snap of the emitter to the segment grid. Intervals that cover no payload row are omitted.
